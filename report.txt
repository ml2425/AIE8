# LangGraph MCP Agent Implementation Report

## Project Overview
This project implements a natural language interface to MCP (Model Context Protocol) server tools using LangGraph. Users can interact with weather, dice rolling, and web search functionality through conversational queries via two access methods: CLI interactive mode and AI assistant integration.

## Architecture

### Core Components
- **MCP Server** (`server.py`): Exposes tools via MCP protocol using stdio transport
- **LangGraph Agent** (`langgraph_agent.py`): REGEX-based natural language processing and tool orchestration
- **Business Logic**: Separate modules for weather (`services/geo_weather.py`) and dice rolling (`dice_roller.py`)

### Data Flow
```
Method 1: User → CLI → LangGraph Agent → REGEX Classification → MCP Tool Call → Response
Method 2: User → AI Assistant → LangGraph Agent → REGEX Classification → MCP Tool Call → Response
```

## Access Methods

### Method 1: CLI Interactive Mode
**Usage**: Run `python langgraph_agent.py` for interactive conversation
**Features**:
- Direct command-line interaction
- REGEX-based intent classification
- Real-time MCP tool calling
- Local execution only

**Example Session**:
```

### Method 2: AI Assistant Integration
**Usage**: Ask questions through AI assistant (like me) who calls the LangGraph agent
**Features**:

- AI assistant handles technical details
- Same REGEX-based classification
- Conversational experience

**Example Flow**:
```

Response: "Weather information: Current weather: 12.1°C, wind 26.7 m/s (dir 243°), code 61. Source: Open-Meteo."

## Transport Protocol

### Current Implementation: stdio Transport
- **Protocol**: Standard input/output communication
- **Access**: Local process-to-process communication
- **Security**: No network exposure, local only
- **Integration**: Works with Cursor MCP integration
- **Future Consideration**: HTTP transport for external access (not implemented)

### stdio Transport Benefits
- ✅ **Secure**: No network ports opened
- ✅ **Fast**: Direct process communication
- ✅ **Simple**: No configuration required
- ✅ **Compatible**: Works with existing MCP tools

## Available Tools

### 1. Weather Tool (`weather_by_place`)
**Purpose**: Get current weather information for any location
**MCP Server Function**: `weather_by_place(place: str)`
**Natural Language Patterns**:
- "What's the weather in Paris?"
- "How's the weather in Tokyo?"
- "Temperature in London"
- "Climate in New York"

**Example Usage**:
```
Query: "What's the weather in Paris?"
Response: "Weather information: Current weather: 12.1°C, wind 26.7 m/s (dir 243°), code 61. Source: Open-Meteo."
```

**Technical Details**:
- Uses Nominatim for geocoding (no API key required)
- Uses Open-Meteo for weather data (no API key required)
- Returns temperature, wind speed, wind direction, and weather code

### 2. Dice Rolling Tool (`roll_dice`)
**Purpose**: Roll dice with various notations
**MCP Server Function**: `roll_dice(notation: str, num_rolls: int = 1)`
**Natural Language Patterns**:
- "Roll 3d6"
- "Roll 3 dice"
- "Roll 2d20k1" (keep highest 1)
- "Roll 4d6 and keep the highest 3"

**Example Usage**:
```
Query: "Roll 3d6"
Response: "Dice roll result: 6, 5, 4 -> RETURNS: 15"
```

**Technical Details**:
- Supports standard dice notation (XdY)
- Supports "keep highest" notation (XdYkZ)
- Converts natural language to dice notation
- Returns individual rolls and total

### 3. Web Search Tool (`web_search`)
**Purpose**: Search the web for information
**MCP Server Function**: `web_search(query: str)`
**Natural Language Patterns**:
- "Search for Python tutorials"
- "Find information about climate change"
- "Look up machine learning"
- "What is artificial intelligence?"
- "Tell me about quantum computing"

**Example Usage**:
```
Query: "Search for Python tutorials"
Response: "Search results: [Returns multiple URLs with content snippets]"
```

**Technical Details**:
- Uses Tavily API for web search
- Returns multiple search results with URLs and content
- Truncates very long results for readability

This starts an interactive session where you can ask questions directly.

### 4. Method 2: AI Assistant Integration
Ask questions through an AI assistant who will call the LangGraph agent internally:
```python
from langgraph_agent import MCPAgent
import asyncio

async def main():
    agent = MCPAgent()
    response = await agent.run("What's the weather in Tokyo?")
    print(response)

asyncio.run(main())
```

### 5. Direct MCP Server Access
Access MCP tools directly without LangGraph agent:
```python
from fastmcp import Client
import asyncio

async def direct_access():
    async with Client("server.py") as client:
        result = await client.call_tool("weather_by_place", {"place": "Paris"})
        print(result)

asyncio.run(direct_access())
```

## Technical Implementation Details

### Intent Classification: REGEX-Based
The agent uses regex patterns to classify user intents:
- **Weather patterns**: `r"weather.*in\s+(\w+)"`, `r"what.*weather.*(\w+)"`
- **Dice patterns**: `r"roll\s+(\d+d\d+(?:k\d+)?)"`, `r"(\d+d\d+(?:k\d+)?)"`
- **Search patterns**: `r"search\s+for\s+(.+)"`, `r"what\s+is\s+(.+)"`

### REGEX vs LLM Comparison
| Aspect | Current (REGEX) | LLM-Based |
|--------|----------------|-----------|
| **Speed** | ✅ Very fast | ⚠️ Slower (API calls) |
| **Cost** | ✅ Free | ❌ Costs money |
| **Accuracy** | ⚠️ Limited patterns | ✅ More flexible |
| **Maintenance** | ❌ Need to add patterns | ✅ Learns from examples |
| **Dependencies** | ✅ Just regex | ❌ Need LLM API |

### MCP Integration
- Direct MCP client calls using `fastmcp.Client`
- stdio transport for local communication
- No additional adapters needed
- Synchronous tool calls within async context

### Response Formatting
- Extracts relevant content from MCP tool results
- Formats responses for user readability
- Handles different result types (weather, dice, search)
- Truncates long search results for readability
